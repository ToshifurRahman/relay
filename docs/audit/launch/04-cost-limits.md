# Launch audit: Free-tier Cost and Limits (7.12.4)

Audit date: 2026-11-22, against `audit/7.12.4-cost-limits` from `main` at `9bf0964`. It covers the
7.12.4 checks and the 7.12.4 items parked in `docs/audit/pre-audit.md` (lines 580-590): the Redis
command budget (`PA-7.8-04`, amended to Redis Cloud) and the LLM calls per ticket (`PA-7.5-03`).
Code was read and measured on the local stack; the only live probes were read-only requests to
`https://ticket-pipeline.onrender.com`.

Severity uses the same scale as the pre-audit: Critical and High block go-live, and a Medium or
Low may ship only as an accepted risk with a reason. Finding IDs are `COST-NN`.

## Handoff

- `docs/deployment.md` (audit-rel): says a keep-awake pinger "spends the allowance anyway" but its
  Neon section also says 100 CU-hours; under the current plan a pinger **exceeds** it (186 vs 100).
  Correct the wording and, if uptime monitoring is wanted, use `/health/live` for the health check
  and the pinger.
- `apps/api/src/lib/config.ts` (audit-rel): consider lowering `SNS_ALERT_MAX_PER_HOUR` from 20 to 1
  (744 emails/month) if the SNS free email allowance must not be exceeded (COST-03).
- `apps/api/src/lib/db.ts` (audit-rel): the pool leaves `connectionTimeoutMillis` at `pg`'s default
  0, so a connect that never completes waits forever. Not a cost ceiling; a reliability note.
- `services/tickets.ts` (owner of replay): if a hard LLM budget is preferred over the accepted risk,
  count replays against the day key or add a replay cap (COST-02).
- `render.yaml` / AWS Console (maintainer): confirm the `$1` budget and its alert recipient; there is
  no repository evidence of the live budget.
