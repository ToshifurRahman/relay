# Launch audit: Security (7.12.1)

Audit date: 2026-11-22, against `audit/7.12.1-security` from `main` at `bc56483`. It covers the
7.12.1 checks and the 7.12.1 items parked in `docs/audit/pre-audit.md` (lines 580-590). Every
check below was run against the real codebase, and the live checks against
`https://ticket-pipeline.onrender.com` with read-only, low-volume probes.

Severity uses the same scale as the pre-audit: Critical and High block go-live, and a Medium or
Low may ship only as an accepted risk with a reason. Finding IDs are `SEC-NN`.

## Notes and limits

- `osv-scanner` and `gitleaks` are not installed on `PATH`, so `bun audit` and the `git log -p`
  scan stand in for them. No unpinned `@latest` tool was fetched.
- The live probes were read-only: headers, 401s, one bogus sign-in, one cross-origin POST that was
  refused before any handler ran. No ticket was created, no lockout was triggered, no load or fuzz
  test ran against production.
- Confirming the Redis key on the live service needs `REDIS_URL`, which this audit does not read;
  the runbook step in `docs/deployment.md` covers it.
- **Cloudflare sole-ingress, verified 2026-11-22 (read-only).** Both the service host and Render's
  origin host resolve to Cloudflare CDN, and Cloudflare refuses a client-supplied
  `CF-Connecting-IP`:

  ```
  $ dig +short ticket-pipeline.onrender.com
  gcp-us-west1-1.origin.onrender.com.
  gcp-us-west1-1.origin.onrender.com.cdn.cloudflare.net.
  216.24.57.18
  216.24.57.16
  $ dig +short gcp-us-west1-1.origin.onrender.com
  gcp-us-west1-1.origin.onrender.com.cdn.cloudflare.net.
  216.24.57.16
  216.24.57.18
  $ curl -sS -D - -H 'CF-Connecting-IP: 203.0.113.9' https://ticket-pipeline.onrender.com/health/live
  HTTP/2 403
  server: cloudflare
  cf-ray: a5e60a6dac1c311c-DAC
  error code: 1000
  ```

  **Residual risk (accepted):** `clientIp()` trusts `CF-Connecting-IP` because Cloudflare is the
  only ingress. The unit tests cover the parsing, and the live service returns the header chain
  above (`server: cloudflare`, `x-render-origin-server: Render`), but neither proves the topology
  stays that way. If the service were ever deployed behind a non-Cloudflare proxy, or reachable at
  the Render origin host directly, a caller could set that header and choose its own rate-limit
  and sign-in-lockout key. Origin lockdown (Cloudflare-only ingress, or a Render IP allowlist) is
  what keeps the trust valid; it is a deployment property, not something this branch enforces.

- Pino ticket-text and PII redaction, `ticket_events.detail`, `ai_interactions` PII, SNS payloads,
  email masking, retention and `/privacy` copy belong to 7.12.2 and were not touched.
